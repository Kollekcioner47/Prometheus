СОСТОЯНИЕ ФАЙЛА Prom+Graf.pptx
=========================================================================

Презентация Prom+Graf.pptx в этом каталоге повреждена и не
открывается. Это следствие технической ошибки при оформлении
новой версии курса, а не дефекта самой презентации: файл попал
под операцию нормализации переводов строк, которая была рассчитана
на текстовые файлы, и двоичное содержимое при ней было испорчено
(размер вырос с 785 КБ до 1,35 МБ).

Файл оставлен на месте намеренно. Если в хранилище есть история
версий, презентацию можно вернуть к состоянию до 11.10.2026 —
это самый простой способ её восстановить.

Для самого курса презентация не нужна: она относится к прежней
версии, а всё её содержание — установка Prometheus, установка
Grafana, node_exporter, AlertManager — разобрано в новых практиках.
Разбор прежней версии ниже опирается на текстовые заметки
из каталога Практика/, и они целы.


Чем была прежняя версия
=========================================================================

Девять практических заметок: установка Prometheus, установка Grafana,
node_exporter, windows_exporter, postgres_exporter, nginx_exporter,
docker_exporter, k8s_exporter, AlertManager. Плюс файл promql.txt
с двумя десятками имён метрик без единого пояснения.

Это не учебный текст, а рабочие заметки, собранные из трёх
источников:

  * статья с чужого сайта, скопированная целиком вместе с оглавлением
    и подписью автора (файл 1_install.txt, строки 13–160);
  * сохранённая страница «Потрясающие оповещения Prometheus»
    из раздела «Коллекция правил оповещения» — файл HTML на 1,6 МБ
    и каталог «Потрясающие оповещения Prometheus _ Коллекция правил
    оповещения_files» с чужими скриптами, шрифтами и картинками;
  * собственные записи по ходу занятий.

Единого оглавления, программы, требований к стенду, разбора ошибок
и проверки результата не было ни в одном файле. Нумерация — 1…
9_AlertManager с заглавной буквы в середине имени файла.


Почему прежняя версия заменена
=========================================================================

1. ИНСТРУКЦИЯ НЕРАБОЧАЯ В РОССИИ
=========================================================================

Это главная причина, и с неё начинается новая практика 5.

  Файл 1_install.txt, строки 151–155:

    curl -s https://packages.grafana.com/gpg.key | sudo gpg ...
    echo "deb https://packages.grafana.com/enterprise/deb stable main" ...

  Файл 2_grafana.txt, строки 2–3:

    wget https://dl.grafana.com/enterprise/release/grafana-enterprise_9.1.4_amd64.deb
    sudo dpkg -i grafana-enterprise_9.1.4_amd64.deb

Оба адреса из российских сетей недоступны: packages.grafana.com
не соединяется, dl.grafana.com не разрешается. Студент, выполняющий
эту инструкцию буквально, останавливается на второй минуте занятия,
а в заметках нет ни слова о том, что делать.

Кроме того, ставилась версия Enterprise, хотя для курса нужна OSS:
Enterprise требует лицензии, и часть возможностей в ней недоступна
без ключа.

В новой версии установка идёт с зеркала Яндекса
(https://mirror.yandex.ru/mirrors/packages.grafana.com/oss/deb),
разобраны два способа установки и отдельно объяснено, почему
зеркало — это тот же самый репозиторий Grafana Labs, а не чужая
сборка. Разбор целиком — практика 5 и приложение 3.


2. ОШИБКИ, НА КОТОРЫХ ОСТАНАВЛИВАЕТСЯ ЗАНЯТИЕ
=========================================================================

  Файл 3_node_exporter.txt, строка 95, и файл 2_grafana.txt, строка 5:

    [Sernanoce]

  В юнит-файле systemd секция называется [Service]. С этой опечаткой
  служба не запускается вообще, а сообщение systemd («Unit ... has
  no ExecStart= setting») не подсказывает, где искать причину.

  Файл 2_grafana.txt, строка 5:

    sudo /bin/systemctl deamon-reload

  Правильно — daemon-reload. Команда с опечаткой завершается ошибкой
  «Unknown command», и это выглядит как поломка systemd, хотя это
  опечатка в тексте заметки.

  Файл 3_node_exporter.txt, строки 68–74 — плейбук Ansible:

    copy: src=/home/engineer/distrib/node_exporter-1.8.2... dist=/home/engineer/distrib_ne mode=0755

  У модуля copy параметр называется dest, а не dist. Плейбук
  не выполнится: «Unsupported parameters for (copy) module: dist».

  Файл 3_node_exporter.txt, строки 74 и 139:

    copy: src=/etc/system/system/node_exporter.service
    ...
    [Sernanoce]

  Файл юнита берётся из /etc/system/system (лишний system) —
  каталога не существует.

  Файл 3_node_exporter.txt, строка 107:

    ansible-playbook -i inventory.ini

  Запуск без имени плейбука: анsible ответит подсказкой об
  использовании, а не выполнит задачу. В этом же плейбуке
  стоит ignore_errors: yes, то есть все ошибки предписано
  игнорировать.

  Файл 9_AlertManager.txt, строки 80 и 69:

    --storage.path=/etc/Prometheus/alertmanager
    sudo systemctl edit --full --force prometheus-alertmanager

  Первая строка: каталог /etc/Prometheus с заглавной буквы — такого
  каталога нет; хранилище Alertmanager помещено в /etc, где хранят
  конфигурацию, а не данные, и куда служба писать не должна.
  Вторая строка: у службы потеряно расширение .service.

  Файл 9_AlertManager.txt, строка 140:

    sudo systemctl stop prometheus-node-exporter

  Служба, созданная в файле 3_node_exporter.txt, называется
  node_exporter. Остановить prometheus-node-exporter на занятии
  не удастся: «Unit prometheus-node-exporter.service not loaded».
  А главное упражнение практики — добиться срабатывания алерта —
  без этого шага не выполняется.

  Файл 6_nginx_exporter.txt, строки 56 и 19:

    Description=Node Exporter Service

  Юнит-файл nginx-экспортёра подписан именем node_exporter —
  след копирования из соседней заметки. В этой же заметке
  противоречие с портом: в тексте сказано «предполагается,
  что мы настраиваем 8080», а в конфигурации nginx указан
  listen 8081.

  Файл 7_docker_exporter.txt, строки 11 и 3:

    смотрим на портале в tarets, появился ли там наш Nginx
    docker run ... --publish 9417:9417 prometheusnet/docker_exporter

  Первая строка скопирована из заметки про nginx дословно.
  Вторая: контейнер публикует порт 9417, а в конфигурации
  Prometheus указан другой порт — цель остаётся DOWN, и причина
  этого в заметке не разобрана.

  Файл 1_install.txt, строки 72–74 и 124–125:

    sudo cp -r ~/Загрузки/prometheus-2.26.0.linux-amd64/consoles /etc/prometheus
    sudo cp -r ~/Загрузки/prometheus-2.26.0.linux-amd64/console_libraries /etc/prometheus
    ...
    --web.console.templates=/etc/prometheus/consoles \
    --web.console.libraries=/etc/prometheus/console_libraries

  Эти строки работали на Prometheus 2.26.0 и перестали работать
  на 3.x: каталоги consoles и console_libraries убрали
  из дистрибутива в Prometheus 3.0. Проверить состав архива
  можно командой tar tzf — ни одного файла с таким именем в нём
  больше нет. Копирование заканчивается сообщением

    cp: cannot stat '.../consoles': No such file or directory

  а служба с флагами --web.console.* не стартует вовсе.
  В новой версии курса это разобрано отдельно: и как устроен
  архив, и почему нельзя переносить команду запуска из старой
  инструкции или из чужого Dockerfile.


3. ВЕРСИИ, КОТОРЫХ УЖЕ НЕТ
=========================================================================

  Файл 1_install.txt      Prometheus 2.26.0 (актуальная — 3.15.0)
  Файл 3_node_exporter.txt node_exporter 1.8.2 в плейбуке
                           и 1.1.2 в ручной части — две разные
                           версии в одном файле
  Файл 5_postgres_exporter.txt postgres_exporter 0.15.0
  Файл 9_AlertManager.txt      alertmanager 0.21.0

Нигде не сказано, что версии зафиксированы или что их нужно
проверять. Команды `prometheus-*.tar.gz` со звёздочкой в файле
3_node_exporter.txt (строка 27) вообще не выполняются: оболочка
не раскрывает звёздочку в URL.

В новой версии версии зафиксированы в методике курса и в README,
а правило «тег latest не используется нигде» проверяется скриптом
tools/validate_files.py.


4. НЕПОСЛЕДОВАТЕЛЬНОСТЬ МЕЖДУ ЗАМЕТКАМИ
=========================================================================

  * Адреса. В файле 3_node_exporter.txt перечислены машины
    10.0.2.2–10.0.2.14, причём один адрес закомментирован
    (#10.0.2.2) без объяснения. В файле 4_windows_exporter.txt
    появляется 10.0.2.8, о котором раньше не было речи.
  * Grafana. Установка Grafana и настройка источника данных описаны
    в файле 1_install.txt (строки 143–161) И в файле 2_grafana.txt.
    Две инструкции расходятся: в первой ставится Grafana из
    репозитория, во второй — пакетом .deb другой версии.
  * node_exporter. В файле 3_node_exporter.txt два способа
    (Ansible и вручную) перемешаны в одном тексте, и оба содержат
    ошибки; какой из них основной, не сказано.
  * Конфигурация Prometheus. В файле 1_install.txt отступы
    в static_configs заданы табуляцией (строки 95–99), а в файле
    3_node_exporter.txt — пробелами. Оба файла «рабочие».


5. ГЛАВНОГО В КУРСЕ НЕТ
=========================================================================

Это не про ошибки в командах, а про содержание. В прежней версии
отсутствовало то, ради чего курс и существует:

  * ЯЗЫК PROMQL. Файл promql.txt состоит из имён метрик
    (node_disk_info, windows_os_info) без единого запроса.
    Ни селекторов, ни rate, ни агрегаций, ни гистограмм —
    то есть дашборд построить не из чего. В новой версии PromQL
    отданы две практики (3 и 4), и это самый большой блок курса.
  * ФОРМАТ ЭКСПОЗИЦИИ. Нигде не сказано, что такое метка, чем
    counter отличается от gauge и почему к счётчику нельзя
    применять среднее.
  * ПРАВИЛА ЗАПИСИ. Recording rules не упоминаются ни разу, файла
    правил для них нет.
  * ПРОВЕРКА КОНФИГУРАЦИИ. promtool встречается один раз
    (файл 9_AlertManager.txt, строка 36) как проверка правил;
    promtool check config и promtool test rules не упомянуты.
  * ЮНИТ-ТЕСТЫ ПРАВИЛ. Не упомянуты вообще.
  * ОБНАРУЖЕНИЕ ЦЕЛЕЙ. Кроме static_configs нет ничего:
    ни file_sd, ни relabel_configs, ни metric_relabel_configs.
  * PUSH-МОДЕЛЬ. Pushgateway, textfile collector и
    blackbox_exporter отсутствуют.
  * СВОИ МЕТРИКИ. Клиентские библиотеки и собственный экспортёр
    не разбираются.
  * ХРАНЕНИЕ И МАСШТАБ. retention, кардинальность, устройство TSDB,
    remote_write — не упоминаются.
  * ЭКСПЛУАТАЦИЯ. Резервное копирование, обновление, безопасность
    (у Prometheus и Alertmanager нет встроенной аутентификации —
    это в заметках не сказано ни слова), проверка конфигураций
    в конвейере.
  * РАЗБОР ПОЛОМОК. Ни в одном файле нет ни раздела «если что-то
    пошло не так», ни текста ошибки. Студент, у которого что-то
    не заработало, остаётся без подсказки.
  * ПРОВЕРКА РЕЗУЛЬТАТА. Ни в одном файле нет чек-листа:
    что должно быть в системе после практики.
  * GRAFANA КАК КОД. Провижининг источников данных и дашбордов
    не упоминается; всё делается мышью и теряется вместе с базой.

Отдельно: файл 4_windows_exporter.txt состоит из 20 строк, из которых
инструкция по установке — одна строка «И, затем, установить его».
Файл 7_docker_exporter.txt — 20 строк, файл 8_k8s_exporter.txt —
21 строка, причём kube-prometheus-stack в нём ставится без версии
и без namespace. Считать это практикой на два академических часа
нельзя.


6. ЧУЖИЕ МАТЕРИАЛЫ В РЕПОЗИТОРИИ
=========================================================================

Файл «Потрясающие оповещения Prometheus _ Коллекция правил
оповещения.html» и каталог с его ресурсами — это сохранённая
чужая веб-страница: аналитика, чужие скрипты, шрифты и картинки
общим объёмом 1,6 МБ. Как учебный материал она не используется:
в заметках на неё нет ни одной ссылки. В новой версии примеры
правил оповещения написаны самостоятельно и проверяются
юнит-тестами promtool.


Что в новой версии вместо этого
=========================================================================

  * 16 практик вместо 9 заметок, два трека — 24 и 40 ак.ч.,
    с совпадающими номерами практик;
  * плавная кривая сложности: каждая практика опирается только
    на предыдущие, и ни один приём не появляется «пока так,
    объясню потом»;
  * объяснения «почему именно так», «зачем это в работе»,
    «чего не делать» в каждой практике;
  * разбор поломок с точным текстом ошибки в каждой практике
    и отдельное приложение app_2_troubleshooting.txt;
  * установка Grafana из зеркала Яндекса с разбором того,
    почему официальный адрес не работает и почему зеркало
    безопасно;
  * две практики PromQL и отдельное приложение-шпаргалка;
  * обнаружение целей, push-модель, свои метрики, хранение
    и эксплуатация — пять практик расширения;
  * два скрипта проверки материалов: tools/check_course.ps1
    и tools/validate_files.py.

Презентация Prom+Graf.pptx оставлена как есть: она относится
к прежней версии и в новой не используется.
