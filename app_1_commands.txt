ЭТО ШПАРГАЛКА, А НЕ УЧЕБНИК. Здесь собраны команды курса «Мониторинг
на Prometheus и Grafana» в том виде, в котором они выполняются

=========================================================================
1.4. ЧЕГО НЕ ДЕЛАТЬ
=========================================================================

ЧЕГО НЕ ДЕЛАТЬ: ставить Prometheus командой apt install prometheus.
В репозитории Ubuntu версия отстаёт на годы, а конфигурация ложится
в неожиданное место. Курс ставит Prometheus из архива GitHub.

ЧЕГО НЕ ДЕЛАТЬ: запускать Prometheus и экспортёры от root. Для каждой
службы в курсе создаётся своя системная учётная запись без домашнего
каталога и без оболочки.

ЧЕГО НЕ ДЕЛАТЬ: использовать тег latest. Ни в образах контейнеров,
ни в командах скачивания: latest не отвечает на вопрос «что у меня
стоит» — а это первый вопрос при разборе поломки.

=========================================================================
2.1. ОБЩИЙ ПОРЯДОК УСТАНОВКИ ИЗ АРХИВА
=========================================================================

Порядок один для Prometheus, Alertmanager, node_exporter, Pushgateway
и blackbox_exporter: скачать архив в /home/engineer/distr, распаковать,
положить двоичные файлы в /usr/local/bin, конфигурацию — в /etc/<служба>,
данные — в /var/lib/<служба>, создать учётную запись, написать
юнит-файл systemd, выполнить daemon-reload и enable --now.

  mkdir -p /home/engineer/distr
  cd /home/engineer/distr
  wget https://github.com/prometheus/prometheus/releases/download/v3.15.0/prometheus-3.15.0.linux-amd64.tar.gz
  tar -xzf prometheus-3.15.0.linux-amd64.tar.gz
  ls -l prometheus-3.15.0.linux-amd64

Что внутри архива Prometheus 3.15.0:

  prometheus                             сам сервер
  promtool                               проверка конфигураций и правил
  documentation/examples/prometheus.yml  пример конфигурации
  LICENSE, NOTICE

  Каталогов consoles/ и console_libraries/ в архиве НЕТ: их убрали
  из дистрибутива в Prometheus 3.0. Проверить состав можно командой
  tar -tzf prometheus-3.15.0.linux-amd64.tar.gz

Копирование в /usr/local/bin и раскладка каталогов:

  sudo install -m 0755 prometheus-3.15.0.linux-amd64/prometheus /usr/local/bin/
  sudo install -m 0755 prometheus-3.15.0.linux-amd64/promtool /usr/local/bin/
  sudo mkdir -p /etc/prometheus /var/lib/prometheus
  sudo chown -R prometheus:prometheus /etc/prometheus /var/lib/prometheus

  Конфигурацию пишут руками; из архива в /etc/prometheus ничего
  не копируется.


=========================================================================
2.2. СИСТЕМНЫЕ УЧЁТНЫЕ ЗАПИСИ
=========================================================================

Prometheus и Alertmanager работают от одной учётной записи prometheus,
каждый экспортёр — от своей. Домашнего каталога и оболочки нет:
это служба, а не человек.

  sudo useradd --system --no-create-home --shell /usr/sbin/nologin prometheus
  sudo useradd --system --no-create-home --shell /usr/sbin/nologin node_exporter
  sudo useradd --system --no-create-home --shell /usr/sbin/nologin postgres_exporter
  sudo useradd --system --no-create-home --shell /usr/sbin/nologin nginx_exporter
  sudo useradd --system --no-create-home --shell /usr/sbin/nologin blackbox
  sudo useradd --system --no-create-home --shell /usr/sbin/nologin pushgateway

Проверка и права на каталоги:

  id prometheus
  getent passwd node_exporter
  sudo chown -R prometheus:prometheus /var/lib/prometheus
  sudo chown -R prometheus:prometheus /etc/prometheus
  sudo chown -R prometheus:prometheus /var/lib/alertmanager
  sudo chown -R prometheus:prometheus /etc/alertmanager


=========================================================================
2.3. ЮНИТ-ФАЙЛ PROMETHEUS
=========================================================================

  sudo tee /etc/systemd/system/prometheus.service >/dev/null <<'EOF'
  [Unit]
  Description=Prometheus
  Wants=network-online.target
  After=network-online.target

  [Service]
  User=prometheus
  Group=prometheus
  Type=simple
  ExecStart=/usr/local/bin/prometheus \
    --config.file=/etc/prometheus/prometheus.yml \
    --storage.tsdb.path=/var/lib/prometheus \
    --web.listen-address=0.0.0.0:9090 \
    --web.enable-lifecycle
  # Срока хранения в аргументах нет: в 3.15.0 флаги
  # --storage.tsdb.retention.time и .size устарели, значение задаётся
  # в prometheus.yml:
  #   storage:
  #     tsdb:
  #       retention:
  #         time: 15d
  Restart=on-failure
  RestartSec=5

  [Install]
  WantedBy=multi-user.target
  EOF

ЗАЧЕМ ФЛАГ --web.enable-lifecycle: он разрешает перезагрузку
конфигурации по HTTP без перезапуска службы. Без него запрос
POST /-/reload вернёт 403, а выставленный наружу флаг — это
возможность перезагрузить конфигурацию кому угодно.

Юнит-файлы остальных компонентов отличаются только ExecStart
и учётной записью:

  node_exporter    --web.listen-address=:9100
  alertmanager     --config.file=/etc/alertmanager/alertmanager.yml
                   --storage.path=/var/lib/alertmanager
  pushgateway      --web.listen-address=:9091
  blackbox         --config.file=/etc/blackbox_exporter/blackbox.yml


=========================================================================
2.4. ВКЛЮЧЕНИЕ И ПРОВЕРКА СЛУЖБ
=========================================================================

После правки любого юнит-файла — daemon-reload. Без него systemd
не увидит изменений и запустит старую версию.

  sudo systemctl daemon-reload
  sudo systemctl enable --now prometheus
  sudo systemctl enable --now node_exporter
  sudo systemctl enable --now alertmanager
  sudo systemctl enable --now pushgateway

  systemctl status prometheus
  systemctl is-active prometheus
  systemctl is-enabled prometheus

  systemctl restart prometheus
  systemctl stop node_exporter
  systemctl start node_exporter

Смотреть логи службы:

  journalctl -u prometheus -n 50 --no-pager
  journalctl -u prometheus -f
  journalctl -u prometheus --since '10 min ago'
  journalctl -u node_exporter -b

Проверить, что служба слушает свой порт:

  ss -lntp | grep -E '9090|9093|9100|9091|9115'
  sudo lsof -i :9090

=========================================================================
3.1. PROMTOOL
=========================================================================

promtool входит в архив Prometheus 3.15.0 и лежит рядом с бинарником.
Проверять конфигурацию нужно до перезагрузки, а не после.

  promtool --version

  promtool check config /etc/prometheus/prometheus.yml
  promtool check config --syntax-only /etc/prometheus/prometheus.yml
  promtool check rules /etc/prometheus/rules.yml
  promtool check rules /etc/prometheus/rules/*.yml
  promtool test rules /etc/prometheus/tests/rules.test.yml

Ожидаемый вывод check config:

  SUCCESS: /etc/prometheus/prometheus.yml is valid prometheus config file syntax

Ожидаемый вывод check rules:

  SUCCESS: 3 rules found

Проверка формата exposition, который отдаёт свой экспортёр:

  curl -s localhost:9200/metrics | promtool check metrics
  cat sample.prom | promtool check metrics

ЧТО PROMTOOL НЕ ПРОВЕРЯЕТ: доступность целей, правильность адресов
и то, что правило действительно срабатывает. Конфигурация может быть
синтаксически верной и при этом бесполезной — поэтому после promtool
смотрят страницу Targets.


=========================================================================
3.2. AMTOOL
=========================================================================

amtool входит в архив Alertmanager 0.34.1.

  amtool --version
  amtool check-config /etc/alertmanager/alertmanager.yml
  amtool config routes show --alertmanager.url=http://localhost:9093
  amtool config show --alertmanager.url=http://localhost:9093

Проверка конфигурации до перезапуска службы — правило курса: сначала
amtool check-config, только потом systemctl restart alertmanager.

Проверить, что nginx и остальные конфигурации целы:

  sudo nginx -t
  sudo nginx -T | grep -A5 stub_status


=========================================================================
3.3. ЮНИТ-ТЕСТЫ ПРАВИЛ
=========================================================================

Файл тестов описывает входные ряды и ожидаемые оповещения. Формат
берётся из files/08_rules/tests/rules.test.yml.

  promtool test rules /etc/prometheus/tests/rules.test.yml
  promtool test rules /etc/prometheus/tests/*.test.yml

Ожидаемый вывод при успехе:

  SUCCESS

Ожидаемый вывод при расхождении:

  FAILED:
    expr: up == 0
    expected: 1 alert, got 0

Тесты правил нужны потому, что правило ломается молча: promtool check
rules скажет SUCCESS, а оповещение не придёт никогда.

=========================================================================
4.1. ПЕРЕЗАГРУЗКА КОНФИГУРАЦИИ
=========================================================================

Перезагрузка без перезапуска службы: данные в TSDB сохраняются,
соединения не рвутся. Работает только при --web.enable-lifecycle.

  curl -X POST http://localhost:9090/-/reload
  curl -X POST http://10.0.2.5:9090/-/reload

Проверить, что перезагрузка прошла:

  curl -s http://localhost:9090/api/v1/query?query=prometheus_config_last_reload_successful

Ожидаемый ответ:

  {"status":"success","data":{"resultType":"vector","result":[{"metric":{},"value":[1700000000,"1"]}]}}

ЧЕГО НЕ ДЕЛАТЬ: включать --web.enable-lifecycle и смотреть на 9090
из сети без аутентификации. Перезагрузку монтируют за обратный прокси
вместе с basic auth.


=========================================================================
4.2. ПРОСТЫЕ ЗАПРОСЫ
=========================================================================

  curl -s 'http://localhost:9090/api/v1/query?query=up'
  curl -s 'http://localhost:9090/api/v1/query?query=up{env="lab"}'
  curl -s 'http://localhost:9090/api/v1/query?query=node_load1'
  curl -s --data-urlencode 'query=rate(node_cpu_seconds_total{mode="idle"}[5m])' \
    http://localhost:9090/api/v1/query

ЧЕГО НЕ ДЕЛАТЬ: передавать запрос с фигурными скобками и кавычками
без --data-urlencode. Оболочка съест скобки, и вы будете разбирать
ошибку своего запроса вместо ошибки Prometheus.

Диапазонный запрос: обязательны start, end и step.

  curl -s --data-urlencode 'query=node_load1' \
    --data-urlencode 'start=2026-01-01T00:00:00Z' \
    --data-urlencode 'end=2026-01-01T01:00:00Z' \
    --data-urlencode 'step=15s' http://localhost:9090/api/v1/query_range

Шаг 15s совпадает с интервалом сбора: мельче брать смысла нет.

5.5. BLACKBOX_EXPORTER, ПОРТ 9115
=========================================================================

Проверка выполняется не запросом метрик, а запросом пробы: адрес цели
и модуль передаются параметрами.

  curl 'http://localhost:9115/probe?target=https://prometheus.io&module=http_2xx'

=========================================================================
6.3. БЕЗЗВУЧНЫЙ РЕЖИМ (SILENCES)
=========================================================================

Дежурный замолкает на время работ. Правило курса: silence ставится
на метку со значением из реестра, иначе он не совпадёт ни с чем.

  amtool silence add alertname=InstanceDown --duration=1h \
    --comment='работы на web1' --alertmanager.url=http://localhost:9093
  amtool silence add instance=10.0.2.13:9100 --duration=30m \
    --comment='обновление app1' --alertmanager.url=http://localhost:9093
  amtool silence add env=lab --duration='2026-02-01T12:00:00Z' \
    --comment='плановые работы' --alertmanager.url=http://localhost:9093

  amtool silence query --alertmanager.url=http://localhost:9093
  amtool silence query instance=10.0.2.13:9100 --alertmanager.url=http://localhost:9093

Продлить или снять досрочно:

  amtool silence expire 8f4b1c2e-0d5a-4b6c-9f11-2a3b4c5d6e7f --alertmanager.url=http://localhost:9093
  amtool silence update --expires=2h 8f4b1c2e-0d5a-4b6c-9f11-2a3b4c5d6e7f --alertmanager.url=http://localhost:9093

ЧЕГО НЕ ДЕЛАТЬ: ставить silence на alertname без instance, когда
работы идут на одной машине. Такой silence замолчит и все остальные
машины с тем же оповещением, и поломку заметят позже.

=========================================================================
9.1. ЧТО ТАКОЕ ЯЗЫК ЗАПРОСОВ
=========================================================================

Запрос всегда начинается с селектора: имя метрики и фильтры по меткам
в фигурных скобках. Пустой селектор {} запрещён — он означает «все
серии всех метрик», и на боевом сервере такой запрос убивает Prometheus.

  node_load1
  node_load1{instance="10.0.2.11:9100"}
  node_load1{instance=~"10.0.2.1[123]:9100"}
  up{job="node",env="lab"}
  {__name__=~"node_load.+"}

Операторы сопоставления: =, !=, =~, !~. Регулярные выражения
привязаны к строке целиком: node_load1{job=~"node"} не совпадёт
с заданием node_exporter.


=========================================================================
9.2. ФУНКЦИИ И ОПЕРАЦИИ: ЧТО ДЕЛАЕТ И КАК ВЫГЛЯДИТ
=========================================================================

  Функция или операция   Что делает                     Пример
  ---------------------------------------------------------------------
  rate()                 средняя скорость роста          rate(node_cpu_seconds_total
                         счётчика за диапазон            {mode="idle"}[5m])
  irate()                скорость по последним двум      irate(node_cpu_seconds_total
                         точкам                          {mode="idle"}[5m])
  increase()             прирост счётчика за диапазон    increase(node_network_receive
                                                         _bytes_total[1h])
  delta()                изменение gauge за диапазон     delta(node_memory_MemFree_bytes
                                                         [1h])
  idelta()               изменение по двум точкам        idelta(node_load1[5m])
  deriv()                скорость изменения gauge        deriv(node_filesystem_avail_bytes
                                                         [1h])
  predict_linear()       когда величина достигнет нуля   predict_linear(node_filesystem
                                                         _avail_bytes[6h], 4*3600)
  histogram_quantile()   квантиль по бакетам             histogram_quantile(0.95,
                                                         sum by (le) (rate(..._bucket[5m])))
  absent()               вернёт ряд, если рядов нет      absent(up{job="node"})
  absent_over_time()     вернёт ряд, если ряда не было   absent_over_time(node_load1[1h])
                         весь диапазон
  topk()                 первые k рядов по значению      topk(5, node_filesystem_avail_bytes)
  bottomk()              последние k рядов               bottomk(3, up)
  count_values()         считает ряды с каждым значением count_values("version",
                                                         node_exporter_build_info)
  clamp_max()            ограничивает значение сверху    clamp_max(up, 1)
  clamp_min()            ограничивает значение снизу     clamp_min(node_load1, 0)
  round()                округляет до шага               round(rate(node_cpu_seconds_total
                                                         [5m]), 0.01)
  sort_desc()            сортирует по убыванию           sort_desc(topk(5, up))
  sort()                 сортирует по возрастанию        sort(up)
  time()                 текущее время в секундах        time() - node_boot_time_seconds
  vector()               превращает число в ряд          vector(1)
  sum by ()              складывает ряды по меткам       sum by (instance) (up)
  avg by ()              среднее по меткам               avg by (instance) (node_load1)
  max by (), min by ()   максимум и минимум по меткам    max by (instance) (node_load1)
  count by ()            считает ряды                    count by (job) (up)
  stddev by ()           разброс значений                stddev by (instance) (node_load1)
  quantile by ()         квантиль по значениям вектора  quantile(0.5, node_load1)
  без агрегации          арифметика и сопоставление      node_memory_MemTotal_bytes -
                                                         node_memory_MemAvailable_bytes
  on() / ignoring()      выбор общих меток при операции  a / on(instance) group_left b
  group_left             берёт метки с левой стороны     sum by (instance) (up)
                                                         / on(instance) group_left
                                                         count by (instance) (up)
  and, or, unless        логические операции над рядами  up == 1 and on(instance)
                                                         node_load1 > 2
  > bool                 сравнение с нулём и единицей    (node_load1 > 2) bool
  offset 1h              сдвиг назад по времени          node_load1 offset 1h
  @ 1700000000           значение на момент времени      node_load1 @ 1700000000
  @ start() и @ end()    границы выбранного диапазона    node_load1 @ start()

ПОЧЕМУ ИМЕННО ТАК в правилах берут rate(), а не irate(): irate
смотрит на две последние точки и на редком сборе даёт рваный график,
который то и дело срабатывает в оповещении. rate() усредняет
по всему диапазону — правило ведёт себя предсказуемо.

ВАЖНО: rate() требует минимум двух точек внутри диапазона. При
интервале сбора 15s и окне [30s] точек ровно две, результат может
быть пустым. Берите окно не меньше четырёх интервалов: [1m] и больше.


=========================================================================
9.3. ГОТОВЫЕ ЗАПРОСЫ КУРСА
=========================================================================

Загрузка CPU по машинам (idle вычитается из единицы):

  1 - avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m]))

Занятая память в процентах:

  100 * (1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)

Свободное место на разделах, кроме служебных:

  100 * node_filesystem_avail_bytes{fstype!~"tmpfs|overlay"}
  / node_filesystem_size_bytes{fstype!~"tmpfs|overlay"}

Скорость приёма трафика в байтах в секунду:

  rate(node_network_receive_bytes_total{device!="lo"}[5m])

Когда закончится место при текущей скорости:

  predict_linear(node_filesystem_avail_bytes{fstype!~"tmpfs"}[6h], 4*3600) < 0

Девяносто пятый процентиль длительности задания своего экспортёра:

  histogram_quantile(0.95, sum by (le) (rate(lab_job_duration_seconds_bucket[5m])))

Количество целей по заданиям:

  count by (job) (up)

Цели, которые не собираются:

  up == 0

Сертификат истекает раньше чем через 14 дней:

  probe_ssl_earliest_cert_expiry - time() < 14 * 24 * 3600

Свежесть задания из textfile или Pushgateway:

  time() - lab_job_last_success_timestamp_seconds > 3600

Топ-10 метрик по числу серий (поиск виновника кардинальности):

  topk(10, count by (__name__) ({__name__=~".+"}))

=========================================================================
10.1. ОПЕЧАТКИ В КОНФИГУРАЦИИ
=========================================================================

  Написано                Должно быть            Что будет
  ---------------------------------------------------------------------
  scrape_interval: 15     scrape_interval: 15s   интервал станет
                                                 нулевым: число
                                                 читается как
                                                 наносекунды
  evaluation_interval: 1m evaluation_interval: 1m то же самое
  retention: 15           retention: 15d         срок хранения
                                                 в наносекундах
  retention.time: 10y     retention.time: 10y    единица обязательна
                                                 и здесь

ЧЕГО НЕ ДЕЛАТЬ: писать единицу времени через пробел — 15 s.
YAML прочитает это как строку «15 s», и Prometheus откажется
запускаться с сообщением о неверном значении длительности.

ЧЕГО НЕ ДЕЛАТЬ: вкладывать static_configs внутрь global. Оба ключа
живут на разных уровнях: global описывает поведение сервера,
scrape_configs — список заданий. Ошибка видна на первом же
promtool check config.

Разделитель в YAML — двоеточие и пробел после него. Запись
job_name:node читается как одно значение, а не как ключ и значение.

  # неверно
  - job_name:node
  # верно
  - job_name: node

Отступы — только пробелы, шаг в два пробела. Табуляция в YAML
запрещена, и глазом она не отличается от пробела:

  grep -Pn "\t" /etc/prometheus/prometheus.yml
  sed -n '1,40p' /etc/prometheus/prometheus.yml | cat -A | grep '\^I'


=========================================================================
10.2. ОПЕЧАТКИ В PROMQL
=========================================================================

  Написано             Должно быть          Что будет
  ---------------------------------------------------------------------
  up = 0               up == 0              parse error: с одним
                                            знаком равенства это
                                            не сравнение
  up =~ 0              up == 0              =~ сравнивает строки
                                            меток, а не значения
  up == "0"            up == 0              сравнение числа
                                            со строкой не сработает
  node_load1 > 2 bool  (node_load1 > 2)    bool пишется вне
                       bool                 скобок условия
  node_load1{job=node} node_load1{job="node"} значения меток
                                            всегда в кавычках
  node_load1[5m]       rate(node_load1[5m]) range vector нельзя
                                            показать в Graph
  {__name__=".+")      {__name__=~".+"}     для шаблонов нужен =~

Две ошибки, которые встречаются чаще остальных:

  # неверно: range vector там, где нужен instant vector
  node_cpu_seconds_total[5m]

  # верно: сначала функция, она возвращает instant vector
  rate(node_cpu_seconds_total[5m])

  # неверно: сравнение скаляра с вектором без учёта меток
  node_filesystem_avail_bytes / 1000000000 > 0.9

  # верно: сначала доля, потом порог
  node_filesystem_avail_bytes / node_filesystem_size_bytes > 0.9

ПОЧЕМУ ИМЕННО ТАК: оператор =~ в селекторе работает с метками
и только с метками. Значение образца им не проверить — для этого
служит == вне фигурных скобок. Запись up =~ "0" синтаксически
допустима, но сравнивает строку метки, которой нет, и всегда
даёт пустой результат.


=========================================================================
10.3. ПОРЯДОК ПРОВЕРКИ ПОСЛЕ ПРАВКИ
=========================================================================

Порядок один и тот же после любой правки конфигурации или правил:

  1. promtool check config /etc/prometheus/prometheus.yml
  2. promtool check rules /etc/prometheus/rules.yml
  3. promtool test rules /etc/prometheus/tests/rules.test.yml
  4. amtool check-config /etc/alertmanager/alertmanager.yml
  5. curl -X POST http://localhost:9090/-/reload
  6. открыть Status → Targets и Status → Configuration
  7. journalctl -u prometheus -n 30 --no-pager

Проверка на одной строке — удобно вставлять в историю и в конвейер:

  promtool check config /etc/prometheus/prometheus.yml && promtool check rules /etc/prometheus/rules.yml && curl -sX POST http://localhost:9090/-/reload

ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ после перезагрузки — сначала смотрят
prometheus_config_last_reload_successful и строку Loading configuration
в логе, а не перезапускают службу. Перезапуск скроет ошибку,
и следующий разбор начнётся с нуля.
