# files/07_containers — файлы практики 7

Каталог относится к практике 7 «Экспортёры в контейнерах и Docker»
(файл `7_containers.txt`). Содержимое всех файлов напечатано и в самой
практике: на занятии конфигурация набирается вместе с преподавателем,
а этот каталог нужен, чтобы взять готовое, если что-то не набралось.

Готовых решающих скриптов здесь нет намеренно. `run_cadvisor.txt` —
не скрипт, а записанная команда `docker run` с разбором каждого
флага: её предмет изучения — сами флаги, а не результат запуска.

## Что лежит в каталоге

| Файл | К какому шагу | Что это |
|---|---|---|
| `prometheus.fragment.yml` | шаг 5 | фрагмент `scrape_configs` с заданием `docker` |
| `run_cadvisor.txt` | шаг 4 | команда запуска cAdvisor и разбор её флагов |
| `docker-compose.yml` | шаги 8 и 9 | стек мониторинга целиком: |
|  |  | Prometheus, Grafana, node_exporter, cAdvisor |

## Как этим пользоваться

1. **`prometheus.fragment.yml`** — это фрагмент, а не полный
   конфигурационный файл. Задание `docker` дописывается в секцию
   `scrape_configs` рабочего `/etc/prometheus/prometheus.yml` на `mon`.
   Отдельно, сам по себе, этот файл Prometheus не запустит: в нём
   описаны только четыре верхних ключа и одно задание. Перед
   перезагрузкой конфигурации фрагмент проверяется командой
   `promtool check config`.

2. **`run_cadvisor.txt`** — команда запуска cAdvisor на `app1`
   целиком, одной строкой, плюс разбор каждого флага: зачем нужен
   каждый том, почему два из них только для чтения и что именно
   означает монтирование `/var/run/docker.sock`. Версия образа
   закреплена: `gcr.io/cadvisor/cadvisor:v0.55.1`.

3. **`docker-compose.yml`** — полный стек мониторинга для `app1`:
   Prometheus, Grafana, node_exporter и cAdvisor. Запускается из
   каталога с файлом командой `docker compose up -d`, останавливается
   командой `docker compose down`. Все образы закреплены по версиям;
   тега `latest` в файле нет ни у одного образа. Grafana в этом стеке
   публикуется на порту **3001**, а не 3000: порт 3000 на стенде занят
   службой Grafana на машине `mon`, и это разобрано в самой практике.

## Чего в каталоге нет и почему

* **`cadvisor.service`** (юнит-файл systemd) здесь не лежит. cAdvisor
  в курсе запускается контейнером, потому что ему всё равно нужны
  привилегии на хосте, а образ — единственный способ получить его без
  сборки из исходников. Оформлять его юнит-файлом нечего: в юните была
  бы одна строка `ExecStart=/usr/bin/docker run ...`, то есть тот же
  `run_cadvisor.txt`, спрятанный от студента.
* **Дашборда Grafana в формате JSON** тоже нет. Для стека из этого
  каталога подходит готовый дашборд с идентификатором 11467 (Docker
  и cAdvisor); как импортировать дашборд и что делать, когда он ругается
  на неизвестный источник данных, разобрано в практике 5.
* **Готовых `.sh` и `.ps1`** нет: практика проверяет, что студент
  понимает смысл команд, а не умеет запускать чужой файл.

## Стенд

Машина `app1` — 10.0.2.13, Ubuntu 26.04 LTS, 2 ядра, 4 ГБ, диск 20 ГБ.
Docker Engine ставится из репозитория `download.docker.com`; версия
на момент подготовки курса — 28.5.1. cAdvisor слушает порт 8080,
сам стек в Compose — порты 9090 и 3001 на `app1`. Единый реестр
сущностей курса — в `МЕТОДИКА_курса.md`, раздел 5.
