Практика 7, шаг 4. Запуск cAdvisor на app1 (10.0.2.13).

Это не скрипт, а записанная команда и разбор её флагов.
Команда выполняется на app1 от пользователя engineer,
который состоит в группе docker.

-------------------------------------------------------------------------
КОМАНДА ЦЕЛИКОМ (одна строка, переносить её не нужно)
-------------------------------------------------------------------------

  docker run -d --name cadvisor --restart unless-stopped --privileged --publish 8080:8080 --volume /:/rootfs:ro --volume /var/run:/var/run:ro --volume /sys:/sys:ro --volume /var/lib/docker/:/var/lib/docker:ro --volume /dev/disk/:/dev/disk:ro --volume /var/run/docker.sock:/var/run/docker.sock:ro --device /dev/kmsg gcr.io/cadvisor/cadvisor:v0.55.1

-------------------------------------------------------------------------
РАЗБОР ФЛАГОВ
-------------------------------------------------------------------------

docker run
  Создать контейнер из образа и запустить его.

-d
  Отсоединиться (detached): команда возвращает управление, а контейнер
  работает в фоне. Без -d терминал остался бы занят выводом cAdvisor,
  и следующую команду набрать было бы негде.

--name cadvisor
  Имя контейнера. Без него Docker выдал бы случайное имя вида
  keen_wiles, и обращаться к контейнеру пришлось бы по нему.

--restart unless-stopped
  Политика перезапуска: поднимать контейнер после падения и после
  перезагрузки машины, но не поднимать, если его остановили руками.
  Для сборщика метрик это правильное поведение: он должен вернуться
  сам, но команда docker stop должна оставаться командой.

--privileged
  Контейнер получает доступ ко всем устройствам хоста и теряет
  ограничения по возможностям ядра. cAdvisor читает статистику ядра
  и без этого не работает. Это осознанная плата за сбор метрик:
  контейнер с таким флагом доверенный и не должен быть доступен
  никому, кроме администратора.

--publish 8080:8080
  Порт 8080 на машине app1 передаётся в порт 8080 контейнера.
  Порт взят из реестра сущностей курса; Prometheus обращается
  к цели 10.0.2.13:8080.

--volume /:/rootfs:ro
  Корень хоста виден контейнеру как /rootfs. Режим ro (read-only):
  cAdvisor только читает. Отдельно от /sys и /var/lib/docker этот
  том нужен, чтобы видеть примонтированные файловые системы
  и считать по ним container_fs_usage_bytes.

--volume /var/run:/var/run:ro
  Каталог /var/run нужен целиком, а не только сокет: там же лежат
  сведения о процессах хоста, по которым cAdvisor сопоставляет
  контейнер и процессы.

--volume /sys:/sys:ro
  Файловые системы cgroup и статистика устройств. Без /sys cAdvisor
  не переживает старт: он читает /sys/fs/cgroup и падает, если
  каталога нет. Именно на этом томе чаще всего ошибаются.

--volume /var/lib/docker/:/var/lib/docker:ro
  Данные Docker: слои образов и метаданные. Нужен для метрик
  по файловой системе контейнера.

--volume /dev/disk/:/dev/disk:ro
  Символические ссылки на диски: по ним собираются метрики
  ввода-вывода по устройствам.

--volume /var/run/docker.sock:/var/run/docker.sock:ro
  Сокет демона Docker. Через него cAdvisor получает список
  контейнеров, их имена и образы — то есть наполняет метки
  name, image и id. Режим ro здесь обманывает ожидания: он запрещает
  менять файл сокета, но не запрещает разговаривать через него.
  Сокет двусторонний, и процесс в контейнере может отправлять демону
  команды так же, как это делает docker на хосте. Подробный разбор —
  в практике 7, шаг 7.

--device /dev/kmsg
  Доступ к буферу сообщений ядра. Из него cAdvisor берёт часть
  сведений о событиях, связанных с контейнерами.

gcr.io/cadvisor/cadvisor:v0.55.1
  Образ и конкретная версия. Тег latest не используется: он не даёт
  ответа на вопрос, что именно запущено на машине, а этот вопрос
  задают первым, когда метрики перестали приходить.

-------------------------------------------------------------------------
ПОСЛЕ ЗАПУСКА
-------------------------------------------------------------------------

  docker ps --filter name=cadvisor
  CONTAINER ID   IMAGE                              STATUS         PORTS
  b7c1e2f0a9d4   gcr.io/cadvisor/cadvisor:v0.55.1   Up 12 seconds  0.0.0.0:8080->8080/tcp

  curl -s http://localhost:8080/metrics | grep -c '^container_'
  1840

  curl -s http://localhost:8080/healthz
  ok

Точное число строк container_* зависит от числа контейнеров на машине,
поэтому в курсе приводится порядок величины, а не точное значение.
