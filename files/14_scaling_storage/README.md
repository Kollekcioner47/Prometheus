# files/14_scaling_storage — файлы практики 14

Каталог к практике 14 «Масштаб, хранение и производительность».
Здесь лежат четыре файла: фрагмент конфигурации Prometheus для
хранения и удалённой записи, набор запросов для измерения
кардинальности, таблица параметров хранения и этот README.
Каждый файл напечатан в самой практике.

## Состав

| Файл | К какому шагу | Что это |
|---|---|---|
| `retention_notes.md` | шаги 2 и 10 | Таблица «параметр → что делает → значение в курсе» |
| `prometheus.fragment.yml` | шаги 6 и 8 | Фрагмент: `storage`, `remote_write`, `queue_config`, `write_relabel_configs` |
| `cardinality_queries.promql` | шаг 3 | Измерение кардинальности и поиск виновника |
| `README.md` | — | Этот файл |

## Готовых скриптов здесь нет

В каталоге нет ни `.sh`, ни `.ps1`, ни `.bat` — как и в остальных
каталогах `files/`. Практика 14 почти вся состоит из замеров:
`du -sh`, `promtool`, запросы к API Prometheus, правка юнит-файла.
Каждый замер делается руками и объясняется на месте. Скрипт,
который «сделает замер и напишет отчёт», лишил бы практику смысла:
цена кардинальности видна только тогда, когда число до и после
получено своими руками.

## Про `prometheus.fragment.yml`

Это **фрагмент**, а не готовый `prometheus.yml`. Он не заменяет
конфигурацию стенда и не проверяется `promtool` как самостоятельный
файл: в нём нет обязательных для полного файла секций, потому что
они уже есть на стенде с практики 2. Студент переносит из фрагмента
только те блоки, которые разбираются в практике 14, и вставляет
их в свою конфигурацию.

В фрагменте намеренно оставлены заполнители вида `<VM_HOST>`:
адреса VictoriaMetrics в курсе нет, стенд для неё не поднимается.
Заполнитель виден глазом и не даёт скопировать блок, не подумав,
что в нём должно стоять.

## Про `cardinality_queries.promql`

Запросы написаны так, чтобы их можно было выполнить на стенде как
есть: они опираются только на внутренние метрики Prometheus
(`prometheus_tsdb_*`, `prometheus_target_*`) и на собранные ранее
метрики стенда. Ни один запрос не требует правки под свой стенд.

Первый запрос в файле — `prometheus_tsdb_head_series`. Он даёт
общее число рядов в памяти и сам по себе ничего не объясняет:
объяснение появляется, когда рядом оказывается число имён метрик
и список самых крупных имён.
