files/16_final_5day — файлы итоговой работы трека «5 дней»

Практика 16 новых инструментов не вводит. Здесь лежит эталонная
конфигурация «как в продакшене» для учебного стенда: то, к чему
студент приходит, собрав всё из практик 1–15 вместе. Каждый файл
напечатан в 16_final_5day.txt до символа — целиком, кроме
dashboard.json: в практике он напечатан сокращённо (приведены
заголовок, uid, настройки времени и переменные, а массив panels
обозначен многоточием), полный JSON — здесь.

Что важно про эти файлы

Обнаружение целей только из файлов. В prometheus.yml нет ни одной
секции static_configs внутри задания node: цели берутся из
targets/node.json через file_sd_configs. Это решение из практики 11,
и здесь оно доведено до конца — добавить машину в мониторинг можно,
не трогая конфигурацию Prometheus и не перезапуская службу.

Пути в prometheus.yml абсолютные. В практике 15 разобран случай,
когда promtool check config не находит файл правил из-за
относительного пути: promtool ищет относительно каталога запуска,
а Prometheus — относительно каталога конфигурации, и эти два
каталога совпадают не всегда.

Блок remote_write оставлен заглушкой. Он присутствует
и закомментирован, потому что в стенде курса отдалённого хранилища
нет. Записан он для того, чтобы студент видел место, куда этот блок
встанет, и понимал, что на сбор и оповещения он не влияет.

Секретов в файлах нет. Токен бота и пароль SMTP в alertmanager.yml
заменены учебными заглушками вида REPLACE_WITH_TOKEN. Значение
Console47 — учебный пароль стенда из методики курса; он опубликован
в тексте курса сознательно, потому что стенд изолирован.

Чего в этом каталоге нет

Готовых скриптов (sh, ps1, bat) здесь нет и быть не должно: файлы
этого каталога — конфигурация, а не автоматизация. Команды проверки
напечатаны в практике и в checklist.md текстом, чтобы их набирали
руками, а не запускали одним файлом.
