# Каталог files/11_service_discovery/

Файлы практики 11 «Обнаружение целей и перемаркировка».
Все они изучаются в тексте практики и напечатаны там целиком.

## Что за файлы

| Файл | К какому шагу | Как использовать |
|---|---|---|
| `targets/node.json` | шаг 6 | список целей задания `node` для `file_sd_configs`; копируется в `/etc/prometheus/targets/node.json` |
| `targets/extra.json` | шаг 7 | второй файл обнаружения; показывает добавление машины без перезапуска Prometheus |
| `prometheus.fragment.yml` | шаг 15 | фрагмент `scrape_configs` с `file_sd_configs`, `relabel_configs` и `metric_relabel_configs` |
| `relabel_examples.md` | шаг 16 | таблица «действие → что делает → пример» и разбор трёх правил |

## Чего в каталоге нет

Готовых решающих скриптов здесь нет и быть не должно: студент,
запустивший готовое, не поймёт ничего. `targets/*.json` — это
данные для механизма обнаружения, а не программа: Prometheus
читает их сам раз в `refresh_interval`.

## Как пользоваться

Файлы берут там, где запись не набралась, и сверяют с тем, что
напечатано в практике. Файл `prometheus.fragment.yml` нельзя
положить вместо `/etc/prometheus/prometheus.yml`: это фрагмент
одного раздела `scrape_configs`, без `global`, `external_labels`
и `alerting`. Задание `node_filtered` из фрагмента на стенде
заводить не нужно — оно там только для того, чтобы увидеть
действие `keep` в работе.

Пути и имена в файлах совпадают с реестром сущностей курса:
`mon` 10.0.2.5, `web1` 10.0.2.11, `db1` 10.0.2.12, `app1` 10.0.2.13,
порты 9100 и 8080, каталог обнаружения `/etc/prometheus/targets`.
