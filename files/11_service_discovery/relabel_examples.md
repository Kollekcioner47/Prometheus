# Примеры relabel_configs

Все примеры записаны для целей стенда курса: машины mon 10.0.2.5,
web1 10.0.2.11, db1 10.0.2.12 и app1 10.0.2.13 — с теми адресами,
которые перечислены в реестре сущностей. Адреса вымышленными быть
не могут: правило перемаркировки проверяется только на живых целях,
а не на бумаге.

## Действия

| действие | что делает | пример |
|---|---|---|
| `replace` | пишет `replacement` в `target_label`, если `regex` совпал со склеенной строкой | `- source_labels: [role]`<br>`  regex: node`<br>`  target_label: job`<br>`  replacement: node` |
| `keep` | оставляет цель только при совпадении с `regex`, остальные выбрасывает | `- source_labels: [role]`<br>`  regex: node`<br>`  action: keep` |
| `drop` | выбрасывает цель при совпадении с `regex` | `- source_labels: [role]`<br>`  regex: docker`<br>`  action: drop` |
| `labelmap` | создаёт обычные метки из служебных: имя новой метки берётся из `regex` | `- action: labelmap`<br>`  regex: __meta_kubernetes_pod_label_(.+)` |
| `labeldrop` | удаляет метки, чьи имена совпали с `regex` | `- action: labeldrop`<br>`  regex: role\|source` |
| `labelkeep` | оставляет только метки, чьи имена совпали с `regex` | `- action: labelkeep`<br>`  regex: job\|instance\|env` |
| `hashmod` | пишет в `target_label` остаток от деления числа, посчитанного от строки, на `modulus` | `- source_labels: [__address__]`<br>`  modulus: 2`<br>`  target_label: __tmp_shard`<br>`  action: hashmod` |

## Параметры

| параметр | по умолчанию | что делает |
|---|---|---|
| `source_labels` | нет | список меток, значения которых склеиваются в одну строку |
| `separator` | `;` | строка, которой склеиваются значения `source_labels` |
| `regex` | `(.*)` | шаблон RE2, привязанный к строке целиком |
| `target_label` | нет | метка, с которой работает действие |
| `replacement` | `$1` | новое значение `target_label`; в нём работают группы из `regex` |
| `action` | `replace` | что делает правило |
| `modulus` | нет | делитель для `hashmod`, обязателен только для него |

## Три примера с разбором

### Разделить цели между двумя Prometheus

    relabel_configs:
      - source_labels: [__address__]
        modulus: 2
        target_label: __tmp_shard
        action: hashmod
      - source_labels: [__tmp_shard]
        regex: 0
        action: keep

Остаток от деления считается от адреса, поэтому одна и та же цель
всегда попадает в одну и ту же половину. Это важное свойство: если
бы деление было случайным, цели переезжали бы между экземплярами
при каждом опросе, и графики рвались бы на каждом переезде.

### Оставить только нужные разделы файловой системы

    metric_relabel_configs:
      - source_labels: [fstype]
        regex: squashfs|iso9660|tmpfs
        action: drop

Правило применяется к уже собранным метрикам, поэтому в нём нельзя
ссылаться на `__meta_filepath`: к этому моменту служебные метки
удалены. Зато здесь работает `__name__` — имя метрики, которого
нет на стадии перемаркировки цели.

### Переименовать метку узла кластера в обычную

    relabel_configs:
      - source_labels: [__meta_kubernetes_node_name]
        regex: (.+)
        target_label: node
        replacement: $1

После такого правила в ряду появится метка `node` с именем узла
кластера, а служебная метка доживёт до конца перемаркировки
и будет удалена вместе с остальными.

## Три ошибки, которые видно в таблице

* `regex` без привязки: шаблон `web` совпадёт с меткой `web`,
  но не с `web1`;
* `keep` без `source_labels`: строка окажется пустой, `.*` совпадёт
  с ней, и правило не отфильтрует ничего;
* `separator` по умолчанию: склейка двух меток даёт строку
  `10.0.2.11:9100;web1`, и `regex`, написанный под один адрес,
  не совпадёт ни с чем.
